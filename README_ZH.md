# GFT-Merge

把不同 AI 工具里的会话合进一个**池子**，再拿池子在任一工具里开一个新会话接着干。本地运行，数据只在本机。

目前支持 **Claude Code** 和 **Codex**。

## 开始

需要 Node.js 22 以上，以及已经装好并登录的 Claude Code 和/或 Codex。

```bash
npx gft-merge
```

浏览器会打开 `http://127.0.0.1:4319`。也可以全局安装后运行 `gft-merge`。

## 用法

- **上面**：每个工具一栏，列出最近 30 天的会话。Claude 的列表跟桌面端一致：已归档、已删除的不列，名字用桌面端的；终端里开的会话标「CLI」。
- **下面**：左边是池子列表，右边是选中池子的工作区。
- **往下拖＝放进池子**：会话拖进工作区就成一个球；拖到已有的球上就融合进去。
- **球拖到球上＝融合**：任意两个球都能融合。
- **往上拖＝新建**：把一个球拖到某个工具的区域上，就在那个工具里新建一个会话，第一条消息就是这个球的内容。
- **点一下球＝压缩**：用设置里选的“处理工具”（哪个工具的哪个模型）调一次模型，把球的内容压成一份。压缩中球的虚线圈会转，名字处显示“压缩中…”。压完成为一个整体，不能再拆；可以继续往上融合新的会话，也可以再压。压缩没完成时拖出去，送的是原文。
- **球上的数字**：单个会话的球显示这个会话本身的上下文大小（直接读自工具的记录）；融合或压缩过的球显示拖出去要送的内容的 token 数，由本地分词器数出来，前面带 ≈。
- **名字和成分**：球下方写着里面的会话，前面带工具名；鼠标悬停在名字上显示成分，从列表里把某个会话拖出去就能拆开。
- **移动和移出**：把球拖到左边另一个池子就搬过去；拖出工作区就移出池子。

## 往上拖时会发生什么

GFT-Merge 在那个工具里新建会话（名为「merge · 池子名」），把内容作为第一条消息发进去，并请 AI 先简要汇报它的理解（在做什么、进展到哪、定了什么、没定什么、下一步），然后等你的指示。这是一轮真对话，所以新会话排在工具列表最上面。不装钩子、不改各工具的配置、不插手它们的处理过程。

- **Codex**：新建并发出后立刻返回；回复结束后用 Codex 桌面端自己的 `codex://` 链接打开这个会话。
- **Claude Code**：等 Claude 回完（几秒到一分钟左右，看内容长短），再用桌面端自己的 `claude://resume` 链接把会话导入桌面端并打开。
- 新会话放在来源会话最多的那个项目目录。

为什么不支持发进已有会话：Codex 会话在 Codex 桌面端里开着时，Codex 不让别的程序往里写；Claude 桌面端显示的是自己缓存的内容，别的程序写进会话文件的消息它不显示。两条路都靠不住，所以只做新建。

注意：

- 送的是精简原话：你说的话和 AI 每轮的最终回答，不含中间过程和工具日志。只有你点了压缩，才会调用模型、花你的额度。
- 没压缩的内容全文送；很长时会占满对方的上下文，可以先压缩。
- 目前只在 Windows 上实测过；macOS 和 Linux 上打开桌面端的链接没有验证。

## 命令

`open`（默认）· `serve` · `stop` · `status`，可加 `--port`。

## 数据

默认在 `~/.gft-merge/`（可用 `GFT_MERGE_HOME` 改）：

- `pools/<id>.json`：池子名、里面的球、每个球里的会话和压缩块。
- `pools/<id>.jsonl`：池子里的消息，一行一条。被压缩的会话，原消息随之移除，只留压缩块；原会话本身在各工具里不受影响。
- `settings.json`：启用哪些工具、处理工具用哪个工具的哪个模型。

送出的内容以 `〔GFT-Merge〕` 开头；再次合并时会跳过这类消息，防止来回同步越滚越大。
